# VBT Analyzer — 挙上速度・パワー解析

ウエイトトレーニングの動画からバーの挙上速度・力・パワーを算出し、レップごと／セットごと／日付ごとの推移をグラフ化する。

**ブラウザだけで動く。インストール不要、サーバー不要、費用ゼロ。**
動画も記録もすべて端末内で処理・保存され、どこにも送信されない。

---

映像は2通りの入れ方ができる。

1. **動画ファイルを読み込む** — 既に撮ってある動画を解析する
2. **カメラでその場撮影する** — 撮りながらリアルタイムで速度を表示し、停止すると確定値を出す

---

## 使い方（最短）

**https://vbt-analyzer.github.io/** を開くだけ。インストール不要。
ホーム画面に追加すればアイコンから全画面で起動し、通信が無くても開ける。

開発中はローカルの `index.html` をブラウザで開いても動く（カメラとPWAを除く）。

> **カメラ機能とホーム画面追加は https でしか動かない。**
> ブラウザのカメラAPIも Service Worker も、ファイルを直接開いた状態（`file://`）では使えない。
> 部員に配るときは必ず公開URLから開いてもらうこと。

## 選手の登録

記録を誰のものか区別するため、**その端末で初めて使う人だけ**が名前・学年・性別を登録する。
2回目以降はプルダウンから自分を選ぶだけ。人数が増えても探せるよう、選択肢は学年でグループ分けされる。

- 登録時に**数字4桁のPIN**を決める。他の人が自分の名前で記録できないようにするため
- 「この端末では次回からPINを聞かない」は、**自分のスマホならオン、共用タブレットならオフ**
- 名簿は**端末（ブラウザ）ごと**に持つ。別の端末では登録し直しになる
- 学年が上がったら「選んだ人の情報を直す」で変更する。過去の記録は消えず、記録側の名前も追随する
- 「履歴と推移」タブでは**学年・性別で絞り込める**。未記入の人がいるときだけ「（未設定）」が選択肢に出る
- 性別は「回答しない」を選べる（絞り込みに使わないだけで、記録の中身は変わらない）

### PINの限界（正直に）

このアプリにはサーバーが無く、**PINの照合はすべて手元の端末の中で行われる**。
したがって開発者ツールを使える人には回避できる。
**取り違えと軽いなりすましを防ぐための仕組みであって、本物の認証ではない。**
成績を厳密に保証する用途には使えない。

本物の認証にはサーバー（Firebase等）が必要で、その場合は記録が端末外に保存される。
いまの「データが端末から出ない」設計とは両立しないため採用していない。

PIN は平文では保存せず、選手ごとのソルト付き SHA-256（`crypto.subtle`、
使えない環境では簡易ハッシュ）で保存している。ただし4桁である以上、
総当たりには耐えないことを前提にすること。

### 管理PIN（任意）

共用端末向け。設定しておくと以下に管理PINが必要になる。**なりすまし防止が目的**で、
顧問がデータを集めるための仕組みではない。

- 他人のPINのリセット
- 名簿からの選手の削除
- 記録の一括削除
- JSONの読み込み（他人の名前で記録を足せてしまうため）

設定は「履歴と推移」タブ →「この端末の管理」。忘れると解除できないので注意。

## 記録の持ち出し

書き出せるのは**いま選ばれている選手の分だけ**。共用端末で誰かが書き出しても、
他の部員の記録は含まれない。

| 形式 | 用途 |
|---|---|
| CSV | 表計算ソフトで開く。レップ1本が1行。他の人と比べたいときはこれを持ち寄る |
| JSON | このアプリに読み込み直せる。機種変更のときの引っ越し用 |

ブラウザのデータを消すと記録も消える。定期的に書き出しておくこと。

## 撮影のしかた

| 項目 | 指針 |
|------|------|
| 目印 | バーの端（プレート外側の面かスリーブ）に **蛍光ピンク／蛍光グリーン** のテープを3〜5cm四方。**背景に同じ色が無いこと**が最重要 |
| カメラ | 三脚か床置きで**固定**。手持ちは不可 |
| 向き | バーに**正対**（真横）。斜めだと移動距離が実際より短く出る |
| フレームレート | 60fps以上を推奨。クリーン等の速い種目では必須 |
| 明るさ | 暗いとマーカーの色が沈んで追跡が外れる |

白・黒・銀のテープしか無い場合は、ステップ3の「白/黒/銀の目印」にチェックを入れる（色相ではなく明度で判定するモードに切り替わる）。

## 画面の流れ

1. **映像を用意する** — 「動画ファイルを使う」か「カメラで撮る」を選ぶ
2. **スケール較正** — 映像上の2点をクリックし実寸(mm)を入力。プレート直径450mmが手軽
3. **マーカーの色を指定** — マーカーをクリック。緑の網かけが**マーカーだけ**を覆うようスライダーで調整
4. **セット情報** — 日付・選手・種目・重量
5. **解析** — ファイルなら「解析を実行」、カメラなら「録画開始」→セット実施→「停止して解析」
6. **保存** — 「履歴と推移」タブで推移・荷重-速度プロファイル・推定1RMが見られる

### カメラで撮る場合

- **カメラを開く前に三脚・スタンドで固定する。** 開いたあとに動かすと較正がずれる
- 較正とマーカー指定を済ませてから「録画開始」
- 録画中は画面にレップ数・直前のレップの平均推進速度・速度低下率・マーカー検出率が出る。
  これは**目安**（実時計ベースの簡易計算）。停止後に録画全体を解析した値が確定値
- 「ライブ解析 ○fps」の表示が15fpsを下回るときは端末が重く、ライブの数値は当てにならない。
  確定値は録画データから出すので影響しない
- 撮り終えた録画はそのまま解析に回る。残したい場合は「録画した動画を保存」
- 続けて次のセットを撮る場合、解析後にそのまま「録画開始」を押せばよい（較正はそのまま使われる）
- 録画中は画面が消えないよう画面ロックを抑止する（対応ブラウザのみ）

## 算出している指標

| 指標 | 定義 |
|------|------|
| 平均推進速度 (MPV) | 挙上開始から加速度が −9.8 m/s² を下回るまでの平均速度。負荷管理で最もよく使われる |
| 平均速度 (MCV) | 可動域 ÷ 所要時間 |
| 最高速度 | 挙上中の速度のピーク |
| 力 | 質量 ×（加速度 ＋ 重力加速度）。質量はバー重量（＋任意の追加システム質量） |
| パワー | 力 × 速度。平均は台形積分、最大は瞬時値のピーク |
| 速度低下率 | セット内の最速レップに対する最終レップの落ち幅 |
| 推定1RM | 荷重-速度の回帰直線を最小速度閾値まで外挿した値。**異なる重量のセットが2つ以上必要** |
| 左右ブレ | 挙上中のバーの水平方向の振れ幅 |

## 精度と限界

1台のカメラの2次元映像から縦方向成分だけを取り出している。以下は原理的な制約。

- **較正の2点クリックがずれると、速度もパワーも同じ割合でずれる。** 最大の誤差要因
- カメラが斜め向き／超広角レンズだと、距離が実際より短く出る
- フレームレートが低いほどピーク系の指標が荒れる（平均系は低fpsでもよく合う）
- 加速度は位置ノイズの2階微分にあたり、速度よりはるかに荒れる
- 推定1RMは統計モデルによる外挿値であり、実測1RMの代わりにはならない
- マーカーが一瞬隠れて別の物に飛ぶと、その区間だけ異常な値になる。
  ありえない速度・可動域が出た場合は解析後にその旨を表示するので、しきい値を調整するか撮り直す

→ **他人や他機器と絶対値を比べるのではなく、同じ撮影条件で自分の推移を追う**用途に適している。

```
├── css/style.css           配色（ライト/ダーク両対応）
├── js/
│   ├── kinematics.js       平滑化・微分・レップ検出・パワー算出・荷重速度回帰
│   ├── tracker.js          カラーマーカー追跡（HSV判定＋連結成分の重心）
│   ├── charts.js           依存ゼロのCanvasチャート（折れ線・散布・縦棒）
│   ├── storage.js          localStorage保存（記録・名簿）とJSON/CSV入出力
│   └── app.js              画面制御
├── test/
│   ├── selftest.html       セルフテスト（下記）
│   └── testdata.js         検証用の合成動画（base64）
└── README.md
```

外部ライブラリもビルド工程も無い。ファイルを直接編集して保存すれば反映される。

> ### 更新したら必ず2か所の番号を上げる
> | 場所 | 何のため |
> |---|---|
> | `index.html` の `?v=` | 普通のブラウザのキャッシュ対策 |
> | `sw.js` の `VERSION` | ホーム画面に追加済みの端末に新しいファイルを届けるため |
>
> どちらかを上げ忘れると、部員の端末で**古いファイルが使われ続ける**。
> 2つは同じ番号に揃えておくと迷わない（現在 19 / `vbt-19`）。

## セルフテスト

`test/selftest.html` をブラウザで開くと、既知の運動（正弦波・振幅70px・周期2秒・60fps・バー100kg）で
追跡→速度→パワーの全経路を検証し、理論値との差を表で出す。**改修したら実行して全件PASSを確認する。**

- **テストA**：運動学のみ（理想サンプル）— 平滑化・微分・レップ検出・パワー算出の正しさ
- **テストB**：動画ファイルの解析（再生経路）
- **テストC**：カメラ録画の解析（MediaRecorder経路）— 録画Blob → 長さの確定 → 追跡 → 運動学
- **テストD**：シーク経路（再生が使えないブラウザ・状況でのフォールバック）

直近の実測（2026-08-03、Chromium系）：**全39件PASS**。

| 項目 | 理論値 | A（運動学） | B（動画ファイル） | C（カメラ録画） | D（シーク） |
|------|--------|------------|------------------|----------------|------------|
| 可動域 | 0.700 m | 0.700 | 0.700 | 0.700 | 0.700 |
| 平均速度 | 0.700 m/s | 0.700 | 0.700 | 0.700 | 0.700 |
| 平均推進速度 | 0.700 m/s | 0.698 | 0.724 | 0.724 | 0.724 |
| 平均パワー | 686.5 W | 684.5 | 710.1 | 710.1 | 710.1 |
| 最高速度 | 1.100 m/s | 1.096 | 1.150 | 1.200 | 1.150 |

**ピーク系（最高速度・最大パワー・最大加速度）だけは撮影フレームレートに強く依存する。**
位置の1画素ぶんの誤差が、速度では1階微分、パワーでは加速度（2階微分）を通じて増幅されるため。
対策として (1) 加速度は速度より広い時間窓で平滑化、(2) ピーク値は3点移動平均から取得、
(3) レップの開始・終了は速度がゼロを横切る時刻を線形補間して決める（これで低fpsでも平均速度が
正確に出る）を入れているが、**最大パワーの絶対値を見るなら60fps以上で撮ること**。
上記の実測は端末負荷により実効30fpsで取得したもので、そのため最大パワーは参考値扱いにしている。

## 既知の制約

- **解析中も録画中もタブを前面に置くこと。** 背面に回すとブラウザが動画再生を止め、
  タイマーも1秒に1回まで絞られる。解析は自動でシーク方式に切り替わって完走するが、
  ライブ表示は数値が更新されなくなる（「ライブ解析 ○fps」で気づける）
- `requestVideoFrameCallback` 非対応ブラウザ（Firefox等）ではシーク方式にフォールバックする。
  動作するが遅く（4秒の動画で10秒前後）、時間分解能も落ちる
- カメラ（`getUserMedia`）は https でのみ動く。スマホでファイル直開きでは使えない
- 録画形式はブラウザ任せ（Chromium系は mp4/avc1、他は webm）。
  webm は長さ情報を持たないことがあるため、読み込み時に長さを確定させる処理を入れている
- カテゴリ配色は3系列まで。推移グラフで4種目以上ある場合はセット数の多い上位3種目のみ表示する
